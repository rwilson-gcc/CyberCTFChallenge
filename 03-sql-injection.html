SQL Injection

Learn how attackers manipulate database queries through user input — and how to stop them.

Tell Me

What is SQL Injection?

SQL Injection (SQLi) occurs when user-supplied data is inserted directly into a SQL query without proper sanitisation. An attacker can craft input that changes the query's logic — bypassing authentication, extracting data, or even deleting databases.

It's been the #1 web vulnerability for decades. A single vulnerable login form can expose an entire database of user records.

🔓 Auth Bypass

Input like ' OR '1'='1 can make a login query always return true, bypassing passwords entirely.

📦 Data Extraction

UNION-based injections let attackers append additional SELECT statements to retrieve sensitive tables.

💣 Data Destruction

If the app has write permissions, attackers can run DROP TABLE or DELETE to destroy data.

🕵️ Blind SQLi

Even without visible output, attackers infer data through true/false responses or timing delays.

The Vulnerable Pattern

A naive login query built with string concatenation is trivially exploitable:

// ❌ VULNERABLE — never do this
query = "SELECT * FROM users WHERE username='" + username + "' AND password='" + password + "'";

// If username = admin' --
// Query becomes:
SELECT * FROM users WHERE username='admin' --' AND password='anything'
// Everything after -- is a comment! Password check is skipped.

How to Prevent SQLi

The fix is straightforward: never build SQL queries with string concatenation. Use parameterised queries or prepared statements.

// ✓ SAFE — parameterised query (Python example)
cursor.execute("SELECT * FROM users WHERE username=? AND password=?", (username, password))

// The database treats user input as DATA, never as SQL code.
// Even if username = "admin' --" it's treated literally, not executed.
