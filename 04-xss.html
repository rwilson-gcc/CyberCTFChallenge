Cross-Site Scripting

Explore how attackers inject malicious scripts into web pages viewed by other users — and how proper sanitisation stops it.

What is XSS?

Cross-Site Scripting (XSS) happens when a web application includes unvalidated user input in its HTML output. An attacker can inject JavaScript that runs in other users' browsers — stealing session cookies, redirecting to phishing sites, or defacing the page.

💬 Stored XSS

Malicious script is saved in the database (e.g. in a comment) and executes for every user who views it.

🔗 Reflected XSS

Script is embedded in a URL. When a victim clicks the link, the server reflects it back in the response.

🏠 DOM-based XSS

The attack payload is executed via client-side JavaScript manipulating the DOM — the server may never see it.

🍪 Cookie Theft

document.cookie reveals session tokens. Attackers send these to their server to hijack logged-in sessions.

The Vulnerable Pattern

// ❌ VULNERABLE — direct innerHTML assignment
commentDiv.innerHTML = userInput;

// ✓ SAFE — use textContent or escape HTML entities
commentDiv.textContent = userInput; // Treated as text, not HTML
